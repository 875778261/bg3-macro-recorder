# 2026-10-07

## mouse-script 性能优化（第二轮）

用户反馈「平衡报价→议价后等待很久才进下一轮」，要求缩短等待并缩短两次点击间隔。

### 诊断结论：瓶颈不在延迟配置，在全屏模板匹配

实测单轮耗时构成（3840x2160）：

| 环节 | 改前 |
|---|---|
| 议价按钮全屏定位 | 3454 ms |
| 平衡报价小区域定位 | 3251 ms |
| 全屏抓帧 | 88 ms |
| **配置延迟合计** | **仅 195~490 ms（~1%）** |

根因：`locate()` 默认 `scales=(1.0,0.9,1.1,0.8,1.25)` 跑 5 个尺度，
全屏匹配一次约 600ms。且 `locate_balance` 因锚点未命中回退全屏。
**结论：只调延迟参数最多快 1.07 倍，收益极小。**

### 所做修改

`core.py`：
1. `TemplateFinder` 增加 `_last` 位置缓存 + `hint/set_hint/forget`，
   `locate()` 改两级：先在上次位置附近**单尺度**局部搜（~15ms），
   失败才回退全屏多尺度（~600ms/尺度）。
2. `scales` / `hint_radius` 改为构造参数，可从 config 配。
3. `_match()` 守卫从 `>=` 改 `>` 并加前置尺寸检查，修 OpenCV 断言崩溃。
4. **局部搜索框 bug**：模板是 424x62 宽扁形，原按 `tw//2+40` 算半径得到
   328x440 窄条，**比模板还窄**导致 matchTemplate 抛
   `_img.size().width <= _templ.size().width`。
   修法：局部框改为保证 `>= tw+8 / th+8`。
5. `Screen.grab(region)` 支持 ROI，新增 `grab_around(cx,cy,pad)`、`_clip()` 越界裁剪。
6. `human_move(close_px=)` 近距免移动；`human_click` 的
   写死 `sleep(0.02~0.06)` 提为配置 `pre_click_delay_ms`。

`auto_bid.py`：重写主循环，接入 `acquire_anchor()`（有 hint 走 ROI 抓帧+
局部匹配，无 hint 走全屏）、`_to_global()` 坐标换算、`wait_price_settle`
在 `roi is None` 时直接返回不再白抓一帧。

`check.py`：跟上新签名 `locate_balance(finder, frame, region, anchor)`，
并报告一次缓存复检耗时。

`config.json`：新增 `match_scales:[1.0]`、`hint_radius_px:220`、
`roi_pad_px:320`、`skip_move_below_px:160`、`pre_click_delay_ms:[5,15]`；
延迟下调 `step_delay_ms:[15,40]`、`round_delay_ms:[40,90]`、
`move_duration_ms:[20,45]`。

### 结果

| | 改前 | 改后 |
|---|---|---|
| 单轮 | ~6900 ms | ~180~300 ms |
| 速度 | 0.14 轮/秒 | ~3~5 轮/秒 |

真实画面自检：议价 (1918,2068) 匹配度 1.000、平衡报价 (1918,1958) 匹配度
1.000 状态可点、**缓存复检 11ms**。

### 坑（重要）
**模板匹配自测必须用纯合成底图**。我两次误用「真实屏幕截图」当测试画面，
但当时不在交易面板，贴模板当然匹配不上 → 误判成代码 bug。
调试时先用 `rng.integers` 造噪声底图 + 模板置于 ROI 中心（避免溢出边界）。
另外模板中心若贴近 ROI 边缘，模板会超出裁剪区导致假阴性。
