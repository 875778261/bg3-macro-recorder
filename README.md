自动循环执行「平衡报价」→「议价」。

## ⚡ 快速方案：录制回放（推荐，最快 5 倍）

坐标固定，视觉识别只在首次定位有价值。录一次，之后直接回放。

```bash
# 1. 录制（按 F9 开始/停止，期间正常点几轮）
.venv/Scripts/python.exe macro.py record

# 2. 回放
.venv/Scripts/python.exe macro.py play --gap 150
```

**实测：4.98 轮/秒（201 ms/轮），成功率 100%。**
相比图像识别方案（0.9 轮/秒）快约 5.5 倍。

回放仍保留全部安全机制：金色判据检查按钮可点性、报价区验证是否真的填入、
兜底处理白送弹窗。区别只是**不再每轮做全屏模板匹配**（改用 60x60 小块采样，
8ms，快 8 倍）。

| 方案 | 单轮耗时 | 速度 |
|---|---|---|
| 图像识别 `auto_bid.py` | ~1100 ms | 0.9 轮/秒 |
| **录制回放 `macro.py play`** | **~200 ms** | **5.0 轮/秒** |

慢的根源不是代码，而是为防「点太快被吞」而设的 400ms 点击间隔
（两击 = 800ms）加上每轮的图像匹配开销。录制回放把间隔降到 150ms。

## ⚠️ 必读：「确定捐赠这些物品？」是失败告警

正常流程：点「平衡报价」→ 游戏自动填入合适金额 → 点「议价」→ **交易完成，不弹窗**。

如果弹出：

> **确定捐赠这些物品？** —「你不会从这次交易中获得任何金币。是否确定继续？」  [是] [否]

**说明上一步「平衡报价」的点击被游戏吞掉了** —— 报价栏还是空的，
游戏发现这单交易你什么都得不到，于是问你是否确定白送。

**根因是点击太快。** 最早我误以为要事后关掉弹窗，那把失败固化成了永久失败
（每次都点「否」，交易永远完不成）。正确做法是**不让它失败**。

## 原理

核心是**验证闸门**，不是猜间隔、也不是事后收拾：

1. **清场** —— 若发现弹窗，说明上一轮平衡报价失败，关掉后重做该轮。
2. **定位** —— 用「议价」按钮作面板锚点，优先在**上次命中位置附近**做单尺度
   局部匹配（约 15ms）；丢失时才回退全屏多尺度匹配（约 600ms/尺度）。
3. **判定可用性** —— 用**高饱和金色像素占比**判断「平衡报价」是否可点：
   - 可点（金色描边+金字）：金色占比 ≈ **74%**（实测自你的截图）
   - 禁用（整体去饱和）：金色占比 ≈ **0%**
   - 阈值 `enabled_gold_ratio = 0.25`，分离度约 74 个百分点

   > 曾用 B-R 蓝红差判据，**方向完全搞反**：「平衡报价」是金色按钮
   > （B-R≈-26 为负），被判成禁用 → 脚本一直等待、毫无反应。

4. **点完平衡报价 → 验证报价栏已填入**（`wait_price_filled`）★关键
   - 判据：报价区域的**亮像素占比** >= `price_filled_ratio`
   - 已填入时占比会从 0% 跃升到 3% 左右
   - **未填入 = 点击被吞**，退避 `retry_backoff_ms` 后重试，
     **绝不点「议价」** —— 那正是弹窗的成因
5. **验证通过才点议价** —— 此时交易正常完成，不会有弹窗
6. **保险** —— 若仍意外弹窗，关掉并记为失败，下轮退避重来

> ⚠️ **第 4 步需要先配置 `price_roi`**，否则无法验证，闸门失效。
> 见下方「必须做的一次性配置」。

## 必须做的一次性配置

```bash
.venv\Scripts\python.exe calibrate.py --price
```

在弹出的画面里框选**「出价/要价」两列数字 + 下方物品格**的矩形。
脚本会用当前画面自动标定阈值。

为什么要做：这是整个修复的地基。没有它，脚本无法区分
「平衡报价生效了」和「点击被吞了」，只能盲目地点议价，于是弹窗不断。

自检：`check.py` 会显示 `price_roi` 是否已配置。

环境已装在 `.venv/`，直接用该解释器运行。

```bash
# 0. 开跑前自检（只读，不点击）
.venv/Scripts/python.exe check.py

# 1. 校准：打开游戏交易面板，然后运行
.venv/Scripts/python.exe calibrate.py

# 2.（可选，更稳）采集报价数字区域
.venv/Scripts/python.exe calibrate.py --price

# 3. 开始循环
.venv/Scripts/python.exe auto_bid.py
```

## config.json 说明

| 键 | 含义 |
|---|---|
| **`handle_dialog`** | **是否自动关闭议价确认框（点「否」）。必须为 `true`，否则会误操作** |
| `dialog_wait_ms` | 点议价后等确认框出现的超时，默认 1500 |
| `dialog_poll_ms` | 确认框轮询间隔，默认 50 |
| **`enabled_gold_ratio`** | 平衡报价可用性阈值（金色像素占比）。可点≈74%，禁用≈0%，默认 0.25 |
| `balance_wait_ms` | 平衡报价禁用时，最多等它变可取的时长 |
| `balance_poll_ms` | 等待时的轮询间隔 |
| `min_click_gap_ms` | **硬下限：任意两次点击至少间隔多少毫秒**。由节流器强制保证 |
| `window_title_keywords` | 前台窗口标题须包含其一，否则不动作。填 `[]` 则不校验 |
| `template_threshold` | 模板匹配阈值，调高更严格 |
| `match_scales` | 匹配尺度列表。**`[1.0]` 最快**；改分辨率后改回 `[1.0,0.9,1.1]` |
| `hint_radius_px` | 局部快搜半径，默认 220 |
| `roi_pad_px` | ROI 抓帧边距，默认 320 |
| `**price_roi**` | **报价验证区 `[x,y,w,h]`。未配置则验证闸门失效，必须用 `calibrate.py --price` 配置** |
| `**price_filled_ratio**` | **报价区「亮像素占比」阈值，默认 0.01（1%）。由 calibrate 自动标定** |
| `max_balance_retries` | 连续多少次「平衡报价」未生效后暂停重试 |
| `retry_backoff_ms` | 判定失败后的退避时长
| `verify_interval_ms` | 数字变化轮询间隔 |
| `max_verify_wait_ms` | 等待数字变化的上限，超时也继续（速度优先） |
| `move_duration_ms` | 鼠标移动耗时区间 |
| `skip_move_below_px` | 距离小于此值直接点击，跳过移动。默认 160 |
| `pre_click_delay_ms` | 点击前停顿区间（发生在节流**之前**，可叠加） |
| `round_delay_ms` | 两轮之间的额外间隔（在节流之外） |
| `max_rounds` | 最大轮数，`0` 为不限 |
| `click_jitter_px` | 落点随机抖动半径 |

### ⚠️ 关于点击间隔

**`step_delay_ms` 已废弃，请勿再设置。**

现在改由 **`min_click_gap_ms` 统一强制**：节流器在每次实际点击前阻塞到距上次
点击已满该值，与调用路径无关，因此**任意两次点击的间隔都不小于它**。

实测 150/200/300/500 均精确生效。想调就改这一个值。

**代价**：每轮固定 2 次点击，单轮最少 `2 × min_click_gap_ms`。

> 注意：如果你之前遇到过「议价→议价」并以为是间隔太短导致的 —— 那其实是
> **确认弹窗**没处理（见本文开头）。间隔调大到 350ms 也治不好它。

### 校准要点

- **务必框「平衡报价」按钮的亮态（可点）版本**。禁用态是灰的，脚本靠亮度判断可用性。
- 框选时只框按钮本身，**不要带太多周围背景**，背景越多越容易误匹配。
- 校准完成后不要改分辨率或 UI 缩放，否则需重做。

## 常见现象

**脚本一直打印「已等待 5000ms 仍不可点」**

说明「平衡报价」处于禁用态 —— 通常因为报价已经处于平衡状态（出价=要价），
游戏就没有需要平衡的东西了。这是游戏的正常逻辑，不是 bug。

此时脚本会**跳过议价、本轮不做任何点击**，直到它变可点。程序不会因此空转点坏。

**总弹「确定捐赠这些物品？」**

说明「平衡报价」点击持续被吞。检查两点：
1.  是否已配置（跑 `calibrate.py --price`）—— 没配置则闸门失效
2. 看进度行的「平衡报价成功 N/M」百分比。偏低就调大 `min_click_gap_ms`

**进度显示「平衡报价成功 0%」**

`price_roi` 框错了，没包含到真正的报价数字，或 `price_filled_ratio` 偏高。
重跑 `calibrate.py --price` 重新框选。

**画面卡在确认框上**

`handle_dialog` 被关掉了。改回 `true`。
